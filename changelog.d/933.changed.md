An apply no longer undoes a rollback on its own: after `muructl rollback`, an apply whose `serving` key still names the release rolled back from is refused, until the key names another release or that release is promoted again by command. An apply that moves traffic away from a release a command made serving says so in its plan, a plan names each setting it removes from an application, and `muructl apply --prune` leaves the release a rollback restores for a later prune, where it removed it.
