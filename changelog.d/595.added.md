Every process of Muru sets a title, so `ps`, `top` and `htop` tell them apart: `murud` for the daemon, `muru-edge` for the edge, `muru run APP` or `muru serve APP`, `muru host APP@RELEASE`, `muru relay APP@RELEASE` and `muru worker APP@RELEASE GROUP/INDEX`.

The edge counts body bytes received from clients and sent to them, as `muru_request_bytes_total` and `muru_response_bytes_total` by application, release and listener.

`muructl status --processes` shows the instance's processes as the tree Muru supervises, under the daemon, `muructl run` and `muructl serve`: the edge, each release's host, log relay and workers, managed server instances and running commands, with each one's user, uptime, CPU and memory, each worker's requests per second, busy slots, p95 and GIL wait or loop lag over the last second, and the instance's figures. `--app` narrows it, `--all` adds the processes Muru did not start, `--watch` keeps it live and `--json` prints it. The dashboard has the same view as a Processes section, and `/v1/processes`; it is also the MCP tool `processes`, and `live/processes.json` in a debug bundle.
