Added a `budget` check to `muructl doctor`, which says where the node's memory limit comes from, the daemon's configuration file or the daemon's own cgroup, and warns when there is none: every scale-out is then admitted and every release starts whatever memory the machine has. It names the two ways to set one, is a warning that does not fail doctor, and has `warning` true in the JSON document. The daemon's status carries the limit as `budget_memory` and `budget_memory_from`.
