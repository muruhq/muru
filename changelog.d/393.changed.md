Changed the longest wait before an instance of a managed HTTP server release that keeps exiting is started again from 30 seconds to a minute, and the first quick exit after a run that lasted now waits as long as the exit that ended the run.

Changed what happens when a release the daemon starts as it comes up, after a reboot say, fails to start: the start is now tried again after a wait that doubles from one second to a minute, with a `release.restarting` event for each attempt, where the application used to stay down until someone deployed or rolled back. A managed HTTP server release follows its `restart` table. A deploy that fails still fails at once.
